# XR Kaigi 2026 表示の仕組み

役割ごとにページが分かれていて、開いた瞬間からその役割で使える。
中身（見出し・画面の文字・台本）は `content.js` だけ。スライド作成チャンネルの台本からそのまま写している。文言はAIが作らない。

| ページ | 使う場所 | 中身 |
|---|---|---|
| `presenter.html` | Macの本体画面（全画面） | 台本・画面の文字・次のページ・残り時間・投影の確認・機能の出し入れ・録画・姿の位置合わせ |
| `projector.html` | 拡張ディスプレイ（スクリーン） | 普通のスライド風の表紙 → 粒になってほどけて3D空間が現れる。文字・写真が空間に並び、切り替わるたびに動いて入れ替わる。登壇者の切り抜きの姿が空間に立つ。右にハッシュタグのQRと投稿 |
| `aura.html` | Aura の Chrome | 発表者ビュー。空間で開くと立っている場所が舞台の原点になり、文字や写真がまわりに並ぶ。手元にスクリーンのミラー・台本・X投稿・残り時間の板 |
| `index.html` | 参加者のスマホ | 発表者に追従、左右タップで見返し、画像保存、Xに投稿。「3Dで見る」でプレゼンの空間を回して見られ、対応端末は「空間で見る」でAR/VR表示 |
| `index.html?replay=…` | 誰でも | 録画の再体験。空間の中に登壇者の姿が立ち、ページと手の動きが録画どおりに再生される |

## 当日の動かし方（Mac）

```
cd xr-kaigi-display
X_BEARER_TOKEN=xxxx node xr-kaigi-20261202/server.mjs
```

1. Chrome（119以降）で `http://localhost:8787/xr-kaigi-20261202/presenter.html` を開き、F で全画面。
2. 「投影画面を選ぶ」→ スクリーンを選ぶと、そのディスプレイに `projector.html` が全画面で開く。
   初回だけ Chrome が「ウィンドウの管理」の許可を聞くので許可する。全画面にならなかった時はスクリーン側を1回クリック。
3. Aura の Chrome で公開URLの `aura.html` を開き「空間で開く」。客席の方を向いて入る（その向きが正面になる）。
   ネットが不安なときは、下の「Aura を Mac に有線でつなぐ」で localhost の aura.html を開く。
4. 登壇者の姿を出すときは C。Mac のカメラの許可を聞かれたら許可。出た姿の位置と大きさは発表者画面のボタンで合わせる（Mac に記憶される）。

トークンなしで起動すると X 欄は出ず、投影の3D表示が横いっぱいになる。`X_MOCK=1` でテスト投稿。

## 発表者画面のキー

| キー | 動き |
|---|---|
| ← → / Space / PageUp・PageDown | ページ送り（投影・Aura・参加者にも届く） |
| Home / End | 最初 / 最後 |
| T | タイマー開始・停止 |
| S | 投影画面を選ぶ |
| F | 発表者画面を全画面 |
| A | 投影を Aura の視界に切り替え／戻す（全画面のまま） |
| X / Q / C | X投稿欄 / QR / 登壇者の姿 の出し入れ |

うまく動かない機能は自動で隠れ、レイアウトが詰まる。WebGL が使えない環境では投影は文字だけの表示になる。

## Aura の操作

- 右手でつまむ：次へ ／ 左手でつまむ：前へ
- 手元の板を指してつまむ：つまんだまま好きな位置に動かせる（位置は Aura に記憶される）。「手元の板を最初の位置に戻す」で元へ
- 手を伸ばす：近くの文字や写真がふんわりよけて光る（スクリーンにも出る）
- 握る：今いる場所と向きを舞台の原点にし直す

## 録画と再体験

1. 発表者画面の「録画」で開始。Mac のカメラ（切り抜き用）とマイクを使う。止めると Mac のダウンロードに
   `xrkaigi-rec-日付-時刻.webm`（動画）と `.json`（ページの切り替えと Aura の手の動き）が保存される。
2. 再体験：`index.html?replay=` を開いて2つのファイルを一緒に選ぶ。
   公開するときは2つを同じフォルダ（例 `rec/`）に置き、`index.html?replay=rec/xrkaigi-rec-….json` を共有する。
3. 再体験中は「‹ ›」で前後のページの始まりへ飛ぶ。対応端末は「空間で見る」で、目の前に舞台が現れる。

## Aura を Mac に有線でつなぐ（ネットが不調でも Aura で操作する）

Aura のつまみ操作は、ネット（WebRTC と ntfy）と有線（Mac の中継）の両方で Mac に届く。片方が落ちてももう片方で動く。
GitHub Pages の発表者画面と aura.html のまま使える（localhost のページを開き直す必要はない）。

準備（1回だけ）
1. Mac に Node.js（18以降）と adb（`brew install --cask android-platform-tools`）を入れる。
2. Aura の設定で開発者向けオプションと USB デバッグを有効にする。

当日
1. Mac のターミナルで
   `curl -fsSL https://abricheese.github.io/talks/xr-kaigi-20261202/wired.mjs -o ~/xrk-wired.mjs && node ~/xrk-wired.mjs`
   （2回目からは `node ~/xrk-wired.mjs`）。adb reverse は中継が数秒ごとに自動でかける。
2. Aura を USB-C で Mac につなぎ、Aura 側で「USB デバッグを許可」。
3. 発表者画面と aura.html を開く。Chrome が「このデバイス上の他のアプリやサービスへのアクセス」を聞いたら許可（Mac と Aura の両方）。
4. 発表者画面が「Aura：有線でつながっています」（ネットもあれば「ネットと有線で」）になれば OK。

- 中継（wired.mjs）は Mac の 127.0.0.1:8787 だけで待ち受け、abricheese.github.io と localhost のページからしか読み書きできない。
- server.mjs も同じ中継を持つので、ネットが全くない時（下）は server.mjs だけ動かせばよい。
- Aura がネットに出られないときは、Aura で送ったページを Mac が代わりに参加者へ配信する（Mac がネットにつながっていれば）。

## ネットがない時

- Mac と Aura：上の有線でそのまま動く（参加者のスマホへの配信と X 欄は止まる）。
- 最終手段：`projector.html` をダブルクリックで開いても、矢印キーでページ送りできる（同期・X欄はなし）。

## 作り直し

`src/` を編集したら `node build.mjs`（three・qrcode-generator・budoux・@mediapipe/tasks-vision・esbuild が必要）。`build/` が本番用、`build-artifact/` は claude.ai の確認用ページ用。
切り抜きのモデルと wasm は `vendor/mediapipe/` に同梱している（外のサイトに頼らない）。
